프로젝트 개요

클러스터 - OCI Free Tier ARM 노드 3대에 kubeadm으로 직접 구축, Terraform·Ansible로 전면 IaC

배포 - Go 빌더가 BuildKit으로 빌드해 값 저장소에 커밋하면 Argo CD가 적용 (GitOps)

격리 - 앱마다 Namespace, NetworkPolicy, PSS restricted, SA 토큰 미마운트 - 사용자는 kubectl 없이 웹으로만 조작

1. 명령형 배포를 Argo CD 선언형 배포로 전환 - API 서버 권한 35개 → 6개

배경

  • 사용자가 런타임을 Java(8080) → JavaScript(3000)로 바꿔 재배포하면 앱이 응답하지 않음 - Service 갱신이 422로 거부돼 요청이 옛 포트로 감
  • 값이 빠져야 하는 변경마다 replace 예외 분기가 늘어나는 중
  • 외부 요청을 받는 core가 직접 적용하느라 클러스터 전역 권한 35개 보유 - 뚫리면 모든 ns의 Secret과 Pod exec에 닿음

분석

  • strategic merge patch가 포트를 키로 병합해 옛 포트가 남음 - patch로는 지울 값을 표현할 수 없음
  • 장애와 권한 문제의 뿌리는 같음 - core가 바꾸는 방법까지 정해 직접 실행하니 지울 값을 몰라 장애가 나고, 직접 쓰니 권한이 필요

해결

대안판단
A. replace 분기 추가 (기존)변경 유형마다 분기가 늘어남
B. core에서 server-side apply필드 삭제만 해결 - 리소스 삭제와 드리프트 복구는 직접 구현해야 하고, 권한도 그대로
C. Argo CD (선택)Git의 원하는 상태를 외부 요청이 닿지 않는 Argo CD가 적용(SSA, prune, selfHeal), core는 값만 커밋
  • Git에 못 적는 일(Secret, ns 삭제, exec)은 테넌트 ns RoleBinding + VAP로 좁히고, exec는 테넌트별 Go 게이트웨이로 분리

결과

  • 런타임·포트를 바꾼 재배포가 분기 없이 정상 동작 (로컬 재현으로 확인)
  • 플랫폼 정책 변경이 차트 커밋 한 번으로 약 1분 안에 전체 앱에 반영
  • 운영 앱 10개를 재생성 없이 이관 (앱당 1분 미만 중단)
  • API 서버 전역 권한 35개 → 6개 - 뚫려도 시스템 영역에 닿지 않고, exec는 게이트웨이 경유만
블로그 - patch로는 지울 수 없었다: 명령형 배포를 Argo CD 선언형 배포로

2. 배포 완료 기준 재설계 - 사용자 대기 22초 단축

배경

  • 빌드마다 의존성을 다시 설치 → 레지스트리 레이어 캐시 적용
  • 빌드는 26.3s 줄었지만 전체는 7.6s만 감소 - cache export가 이득의 71%(18.7s) 상쇄

분석

  • cache export 26.6s 중 15.6s가 image push 이후 실행 - 배포할 이미지가 있는데도 다음 빌드용 캐시를 기다림

해결

  • export를 줄이는 대신 배포 완료 기준을 Job 종료 → image push 완료로 변경 (cache export는 다음 빌드 몫)
  • 로그에서 push 완료를 감지해 즉시 배포, 감지 실패 시 Job 종료 대기로 자동 fallback

결과

push 완료 → 앱 실행사용자 체감 배포
Before126s408s
After101s (-25s)386s (-22s)
  • 추가 컴포넌트나 리소스 없이 사용자 대기 22초 단축
블로그 - 레지스트리 캐시 적용기: cache export를 배포 대기에서 분리하기

3. DNS Timeout 원인 규명 - K8s 네트워크와 클라우드 정책 충돌

배경

  • BuildKit Job이 auth.docker.io DNS timeout으로 실패해 빌드와 배포가 멈춤

과정

확인 대상검증판단
인터넷 연결같은 Pod에서 git clone 성공배제
CoreDNS재시작 후에도 동일배제
Service / kube-proxyCoreDNS Pod IP 직접 쿼리도 timeout배제
Calico 경로 설정전 노드 routing table 정상route 설정 정상
Cross-node Pod 통신Pod IP ping ✕, Node IP ping ○패킷 drop 확인
  • OCI VNIC anti-spoofing과 Calico native routing의 충돌로 원인 확정

해결

  • source/destination check 해제 대신 Calico IPIP 캡슐화 선택 - 클라우드에 묶이지 않는 K8s 레이어 해결
  • Ansible로 영구화해 클러스터 재구축 때도 자동 적용

결과

  • DNS timeout 제거, 빌드·배포 정상화
블로그 - DNS Timeout 범인 찾기: OCI VNIC 검사와 Calico IPIP

1. CloudFront 502 원인 규명 - 구간 신규 연결 지연 67% 개선 (15.7 → 5.1ms)

배경

  • CloudFront를 거친 백엔드 요청만 502 - ALB 직접 요청과 CloudFront의 S3 요청은 정상 → CloudFront-ALB 구간으로 축소

분석

  • openssl s_client로 확인 - ALB 인증서 CN과 Origin SNI가 달라 SNI mismatch로 원인 확정

해결

대안장점리스크
A. SSL Offloading (선택)핸드셰이크 제거, 인증서 관리 단순화CloudFront–ALB 구간 TLS 미적용
B. 전 구간 HTTPS전송 구간 암호화 유지TLS 오버헤드, 인증서 추가 관리
C. Host 헤더 조정즉시 적용 가능리다이렉트와 쿠키 사이드이펙트
  • 전 구간 TLS 규제 요구가 없어 성능과 운영 복잡도를 비교해 A 선택, 잔여 리스크는 AWS 백서로 평가 후 수용
  • Managed Prefix List + Custom Header로 내 CloudFront를 거친 요청만 ALB에서 허용

결과

  • 502 해결, n=100 측정 15.7ms → 5.1ms로 구간 신규 연결 지연 67% 개선
  • CloudWatch 5xx 알람으로 이상 징후 탐지
블로그 - HTTPS가 항상 정답은 아니었다: CloudFront 502 장애 분석
