네트워크 격리

앱마다 네임스페이스 하나, 들어오는 길은 Envoy뿐이고 나가는 길은 공인 인터넷뿐

격리 층

층장치막는 것
네임스페이스앱마다 app-<hex8> 하나, Argo가 PSS restricted 라벨로 생성root 실행 · 특권 컨테이너 · hostPath
인바운드Calico NetworkPolicy tenant-rules (앱마다 차트가 그림)다른 테넌트에서 들어오는 연결
아웃바운드Calico GlobalNetworkPolicy tenant-egress (tenant 라벨 ns 전체)플랫폼 DB · K8s API · 노드 · OCI 메타데이터
빌드kodeploy-build 전용 build-egress유저 Dockerfile의 RUN이 사설망에 닿는 것
게이트웨이Calico NetworkPolicy order 50 (tenant-rules보다 먼저, 차트가 그림)같은 ns 앱 Pod가 게이트웨이에 닿는 것 · 게이트웨이가 K8s API · DNS 말고 다른 곳으로 나가는 것
Pod 신원앱 Pod는 automountServiceAccountToken: false · runAsNonRoot탈취한 Pod 토큰으로 K8s API 호출 (권한이 걸린 토큰은 게이트웨이 것뿐 - 자기 ns exec만)
  • 앱의 DB · Redis는 같은 네임스페이스 안에서만 열린다. 앱끼리 DB를 공유하지 않고, 각자 자기 스택을 가진다.
  • 정책을 Argo가 그리는 차트에 넣어서, 앱이 생길 때마다 같은 정책이 빠짐없이 따라온다. 사람이 앱마다 손으로 거는 정책은 없다.
  • 테넌트 ns마다 뜨는 exec 게이트웨이(kodeploy-exec)는 그 ns에서 유일하게 K8s API로 나가는 Pod다. 그래서 tenant-rules(같은 ns 전체 허용)보다 먼저 평가되는 order 50 정책으로 따로 묶었다 - 들어오는 건 Envoy(공개 문 8080) · Core(내부 문 8081) · vmagent와 kubelet probe(지표 9090)만, 나가는 건 apiserver 6443과 DNS만. 같은 ns 앱 Pod에서 세 포트 모두 접속이 안 되는 것을 운영에서 확인했다.
